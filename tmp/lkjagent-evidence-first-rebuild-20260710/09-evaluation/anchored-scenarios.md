# Anchored Scenarios

## Shared Floors

All runs use a fresh isolated data store seeded from declared workspace bytes,
the final source binary, one flat configuration, and a real configured endpoint.
Owner turns occur near offsets 0, 180, 420, 660, and 840 seconds. The raw event
clock, decision clock, provider exchanges, workspace manifest, and wall clock
must agree. `scenario_policy.py` owns lower bounds and required check IDs;
project scenarios may strengthen but never weaken them.

## Daily Life And Recall

Use Japanese owner text and an Asia/Tokyo fake date near a local-day boundary.

1. Compose a journal from admitted same-day facts without copying the command.
2. Decompose one mixed request into TODO, calendar, and finance operations.
3. Apply an external note correction and update dependent retrieval/index state.
4. Recall an older seeded fact while ignoring a recent unrelated note.
5. Update the TODO and summarize only verified current records.

Checks prove journal date/path/body, command separation, multi-intent
decomposition, TODO round-trip, older-body recall, semantic date stability across
midnight retry, index membership, zero unresolved navigation debt, and owner
visibility through direct workspace reads.

## Multi-Project Development

Seed two projects with similar names and contradictory project-local facts.

1. Inspect the named repository and cite current source.
2. Answer a question about the other project without cross-project leakage.
3. Edit one bounded Rust behavior, run focused checks, then broad Docker checks.
4. Restart the daemon and resume the same obligation without duplicate effects.
5. Report exact diff, checks, workspace project note, and remaining risks.

Checks prove project separation, source fingerprints, allowed-path diff,
nonempty test logs, canonical conversation continuity, workspace visibility,
context exclusion of the wrong project, and no readiness-only closure.

## Long Artifact And Recovery

Request useful world-history reading material of at least 1,500 words while the
first model output cap is 768 tokens. Inject one real output-limit outcome and a
restart after at least one durable semantic unit.

1. Create an outline and named semantic units.
2. Continue other requested work while sections are written incrementally.
3. Recover by splitting or continuation, never the identical impossible call.
4. Revise one section and invalidate then rerun dependent checks.
5. Verify assembled bytes, manifest, links, length, and response paths.

Checks prove output-limit recovery, changed strategy tuple, immutable unit
resume, all artifact units and files, final byte length, source-linked claims,
check invalidation, and absence of a response-path success before files exist.

## Negative Predicates

Any synthetic idle task, fabricated file, missing provider exchange, copied
campaign database, same-strategy retry, generic ready response, stale check,
wrong-project source, command-as-journal prose, JSON harness exchange, hidden
tool effect, or mostly idle 15-minute loop fails the run.
