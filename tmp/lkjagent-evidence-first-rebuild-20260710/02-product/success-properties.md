# Success Properties

## Correctness

- No imperative goal closes without required effects and checks.
- No summary contradicts the underlying matter state.
- Every mutation is idempotent across retry and crash.
- Context never contains unresolved material contradictions.
- Model-visible tools exactly match persisted admission.

## Usefulness

- A diary command produces a useful dated entry.
- A long artifact completes through bounded units.
- A project request reads relevant project evidence before acting.
- Recovery changes strategy rather than repeating the same failure.
- Workspace recall finds relevant body excerpts, not only recent metadata.

## Continuity

- Active work survives process restart.
- Transient endpoint failure schedules recovery and remains visible.
- No-progress detection forces inspect, split, replan, or clarify.
- The daemon remains responsive to new owner input during long work.

## Efficiency

- Prompt duplication and irrelevant context are measured and bounded.
- Stable prompt prefixes support provider cache reuse.
- Tool views remain small.
- Deterministic work does not call the model.
- Maintenance is incremental and change-driven.

## Observability

- Every decision names selected state, context, tools, budget, and exit rule.
- Every effect has intent, result, fingerprint, and recovery status.
- TUI shows each logical message exactly once and in causal order.
