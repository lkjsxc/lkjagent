# Candidate Pool

## Sources

Discover candidates from:

- owner objective, corrections, preferences, and explicit constraints;
- active obligations, operations, failures, and checks;
- exact workspace records and project files selected by query;
- directory READMEs and bounded index pages;
- recent causally related conversation messages;
- prior matter summaries with provenance;
- observed tool results and external evidence;
- owner-approved long-term memory.

## Candidate Shape

Each candidate has semantic key, claim scope, body or excerpt, source path and
fingerprint, trust, timestamp, effective date, staleness, contamination,
estimated tokens, relevance features, and provenance edges.

## Discovery Routing

The selected runtime state determines discovery. Diary composition searches the
local day and recent owner activity. Project inspect searches the named project
and its linked repositories. Recovery retrieves only the failing operation,
bounded diagnosis, and last known-good evidence.

## External Edits

Scan externally changed workspace files, compute fingerprints, parse safe
metadata, and update search projections before selection. A malformed managed
record becomes an import-review diagnostic. A valid large owner or project file
stays in place and is indexed as external source; only bounded excerpts enter
context. Never move owner bytes merely because they exceed a managed-page cap.
