# Contradictions

## Claim Model

A conflict requires the same subject and predicate, overlapping effective time,
incompatible values, and neither claim superseding the other. Different dated
facts are history, not contradiction.

## Materiality

A conflict blocks only operations that depend on it. Conflicting workspace roots
block a write. Conflicting unrelated finance notes do not block a repository
inspection.

## Resolution Order

1. explicit owner correction;
2. newer measured source with valid fingerprint;
3. deterministic temporal supersession;
4. inspect source files or checks;
5. ask one bounded owner question.

Resolution writes edges from winner to suppressed claims and releases the exact
blocked operation.

## Rendering

Normal prompts never receive both unresolved values. A resolution state receives
a compact conflict card with source refs and allowed resolution operations.

## Drift

If a previously selected source changes, invalidate dependent context frames,
decisions not yet executed, checks, and summaries.
