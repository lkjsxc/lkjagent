# Project Contract

## Multiple Projects

Each project has a stable slug and a root under projects. It may contain:

- README and project brief;
- decisions, tasks, notes, and sessions;
- artifacts and evidence;
- one or more source repositories or linked paths;
- project-specific verification commands.

Create these branches only when the project uses them.

## Source Repositories

Repositories may live inside the project root or be linked through a validated
configured path inside the workspace. Git operations remain bounded to the
selected repository. Never treat a repository README as the only project state.

## Context Routing

A project matter selects project metadata, named repositories, relevant file
excerpts, current tasks, recent decisions, and verification evidence. It does
not pull unrelated life records or every project.

## Development Effects

Before edit, record inspected fingerprint and expected files. After edit, record
diff, focused checks, broader verification, and unresolved risks. A readiness
message cannot satisfy a development obligation.

## Navigation

Project README links only actual direct children and keeps a concise current
map. Long activity moves to dated session records.
