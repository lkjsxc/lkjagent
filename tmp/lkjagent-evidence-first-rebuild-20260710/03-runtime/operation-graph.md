# Operation Graph

## Objective Compilation

Owner intent becomes a matter with explicit obligations. Deterministic rules
compile common verbs:

- record or diary: semantic record plus index and activity evidence;
- create or write: concrete artifact path, content, verification, and response;
- inspect or summarize: source reads, synthesis, and cited response;
- modify code: inspected files, patch, verification, and diff evidence;
- verify: named command or checker result;
- organize: previewed moves, applied moves, link repair, and validation.

The model may help decompose unfamiliar goals, but the harness validates every
operation and derives required evidence.

## Nodes

Operation nodes have semantic names, bounded inputs, outputs, budgets, state,
and checks. Large artifacts use outline-derived section names. Do not create
anonymous serial fragments.

## Edges

Edges express requires, produces, invalidates, supersedes, retries, and blocks.
A selector cannot skip an unsatisfied dependency. A changed source fingerprint
invalidates dependent checks and summaries.

## Replanning

Replanning edits the graph through validated events. It must preserve completed
evidence, explain removed work, avoid duplicate output paths, and prove the new
graph is feasible under budgets.

## Feasibility

Before model work, compare requested size, output cap, context cap, tool limits,
and target file budget. Split or narrow before calling the endpoint.
