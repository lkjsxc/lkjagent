# Loop Engineering

## Inner Runtime Loop

Each quantum performs sense, reduce, select, act, observe, evaluate, and adapt.
Persist the state before and after each phase. The next quantum must consume the
new evidence rather than regenerate the same prompt.

## Matter Loop

At obligation boundaries, compare actual progress with the goal graph. Add,
split, reorder, invalidate, or supersede operations through validated events.
Keep completed evidence and explain every plan change.

## Recovery Loop

Normalize fault, select a repair strategy, alter one or more causal conditions,
try once, and measure. Repetition without a changed condition is a harness bug
and immediately advances the strategy ladder.

## Context Loop

Measure selected evidence against outcome. Promote useful sources, demote
irrelevant sources, recalibrate token estimates, invalidate stale summaries,
and preserve deterministic ordering. Learning changes derived scores and
configuration, not owner facts.

## Maintenance Loop

Observe file and index debt, preview bounded repair, apply transactionally,
validate postconditions, and schedule the next threshold. Never run model
maintenance merely because the daemon has no owner work.

## Development Loop

For each hypothesis: preserve a baseline, implement behind a testable choice,
run deterministic and live combinations, compare task outcomes, adopt or
remove, and record why. Multiple interacting ideas must be tested together.

## Loop Invariant

Every iteration produces progress, a changed strategy, a concrete wait
condition, or a truthful visible blocker. It never produces invisible stasis.
