# Prompt Composition

## Ordering

Compile the prompt after selecting and persisting the decision:

1. stable kernel card;
2. owner policy card;
3. selected state and phase grammar;
4. admitted tool schemas;
5. exact output grammar and stop sequence;
6. explicit volatile boundary;
7. objective and current obligation;
8. bounded source-linked context lanes;
9. active conflict or recovery detail.

## Stable Prefix

Kernel, policy, state grammar, tool schemas, and output grammar use deterministic
ordering and stable wording. Volatile objective, evidence excerpts, and recovery
details follow them. Record prefix length and provider cache usage.

## Material State Differences

- intake asks for classification or one clarification;
- inspect exposes read tools and relevant source lanes;
- act exposes one effect family and content constraints;
- verify exposes checks only;
- recover exposes the selected repair operation and quarantined fault summary;
- report exposes no mutation tools and names verified outputs.

## Validation

Before endpoint dispatch, assert:

- no raw JSON harness metadata or protocol serialization;
- harness JSON is projected to attribute-free path/value cards;
- an explicitly requested source JSON excerpt may appear only as inert,
  source-linked, escaped evidence with a byte and token bound;
- no duplicate semantic fact across prompt regions;
- no unresolved material conflict;
- all source refs resolve to current fingerprints;
- rendered tokens fit the decision budget;
- shown tools and output grammar match the persisted view.
