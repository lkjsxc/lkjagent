# Principles

## Purpose

List the ranked invariants that shape implementation and evaluation.

## Ranked Invariants

1. Honesty: no fake success, placeholder work, or unrun gate claims.
2. Durable authority: state cells and persisted decisions own runtime behavior.
3. Harness direction: Rust owns selection, tools, recovery, and completion.
4. Prompt/admission agreement: the same decision owns both surfaces.
5. Engineered context: prompts are bounded source projections, not transcript dumps.
6. Material recovery: a failed tuple cannot repeat without a changed condition.
7. Safe effects: path, prior bytes, intended bytes, and settlement are durable.
8. Fresh completion: every required obligation has a current passed check.
9. Pure core: reduction, selection, rendering, parsing, and checks are pure.
10. Small ownership: every authored file is at most 200 lines and owns one rule.
11. Observable truth: decisions, exchanges, effects, checks, and messages persist.
12. Container proof: final behavior runs from locked clean-source Compose builds.

## Simplicity

Simplicity means one direct loop, few active state fragments, small tool views,
and deletion of retired authority. It does not mean stateless or unsafe behavior.
